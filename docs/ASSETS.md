## 文本、品牌与其他引用

| 路径 / 位置 | 用途 | 当前状态与处理要求 |
| --- | --- | --- |

| 页面中的“抖音精选”等名称、产品名与品牌文字 | 演示主题和界面灵感 | 无官方关系或商标授权声明；不属于 MIT 商标许可 |

部分缓存稿头部包含“未知作者”、旧开发机 `file://` 地址或与卡片不一致的标题。这些信息只能说明历史处理输入，不能验证公开来源。发布前应移除无用的本机路径，并补充能够核验的来源记录；需要保留时也应避免泄露个人目录信息。

## 为每项素材补齐什么

新增或核实素材时，请记录下面的信息，并把上表状态更新为有依据的结论：

| 字段 | 应填写的内容 |
| --- | --- |
| 文件与用途 | 仓库路径、关联 ID、是否进入构建或演示站 |
| 原始来源 | 原始发布页 URL、作品名称、获取日期 |
| 权利人 | 原作者或能够授权的主体；避免以转载者代替 |
| 许可依据 | 明确的许可证名称、许可页面或书面授权凭据位置 |
| 允许范围 | 是否允许复制、再分发、修改、商用及衍生转写；按实际授权记录 |
| 署名条件 | 必须保留的作者、链接、许可文本与修改声明 |
| 处理决定 | 保留、替换或移除，以及核实人和核实日期 |

未取得可核实授权的文件，应在可分发版本中替换或移除。仅从最新目录删除不会清除既有 Git 历史；需要处理历史时应另行评估并由维护者明确决定，不在普通修复中擅自改写历史。

若你认为某项素材存在归属、署名或传播范围问题，请通过 [仓库 Issue](https://github.com/zuixi01/douyinjingxuan/issues) 提供具体文件、原始作品链接和希望采取的措施。涉及个人信息或不宜公开的凭据时，只提交联系请求，并按 [安全政策](../SECURITY.md) 查找私密渠道。维护者应核对后更正、替换或移除相关内容。
