# 发布检查与路线图

仓库已经公开。本文件用于把“能运行的原型”推进为可持续维护的开源项目，不代表已完成正式版本发布，也不意味着当前适合生产部署。当前没有自动 GitHub Pages 发布流程。

## 本次准备应形成的基础

- 中英文说明覆盖实际能力、安装命令、存储选择和已知限制。
- 贡献、安全、行为与许可文档可供维护者审阅。
- 自动检查覆盖前端测试 / 构建与后端测试；具体结果以目标提交的检查记录为准。
- 失败能被用户看见；测试使用临时存储，避免破坏真实笔记。

这些基础不能替代媒体授权、人工体验和维护者的实际发布决定。

## 首次正式发布前

以下项目由维护者结合目标提交逐项确认，不应提前勾选或用路线图替代结果。

- [ ] 确认原创代码及已有贡献的版权与采用 MIT 的权限，审阅 `LICENSE`，并在许可决定后同步更新 README 中“拟采用”的措辞。
- [ ] 核实 [素材清单](ASSETS.md) 的每项来源、许可、署名及再分发范围；授权未确认的媒体、转写及摘要已替换或从可分发版本移除。
- [ ] 清理发布内容中的旧开发机路径、个人数据、缓存敏感信息和不可复用的外部工具配置；敏感信息曾被提交时，先撤销相关凭据，再另行决定历史处理方式。
- [ ] 确认可分发内容不依赖未提供的本机文件；验证排除 `cache/` 的默认应用构建。若还分发历史根页面或缓存工具，单独核对其可选输入与授权，不把历史依赖混入默认应用说明。
- [ ] 从干净克隆按 README 执行 `npm ci`、`npm run check` 与 `npm audit --audit-level=high`，记录 Node.js 与 npm 版本。
- [ ] 在独立 Python 环境安装 `backend/requirements.txt`，运行 `python -m pytest backend/tests -q`，记录 Python 版本。
- [ ] 在目标提交上检查 CI 结果，包括 Ubuntu / Windows 的 Node.js 22 与 Python 3.11 / 3.13；说明任何跳过、失败、平台限制与未覆盖场景，不把未运行写为通过。
- [ ] 手动检查手机 / 桌面尺寸下的浏览、播放 / 暂停、时间戳跳转、收藏、文本录入、搜索、删除和 Markdown 导出。
- [ ] 分别验证纯前端本地模式和后端模式；确认失败提示清楚、不会悄悄切换保存位置，刷新后的数据来源可理解。
- [ ] 确认 JSON 单进程限制、数据备份方式、无鉴权边界与环境变量说明准确。
- [ ] 检查键盘操作、焦点可见性、弹层关闭、触摸目标与基本文字对比度；记录仍存在的无障碍问题。
- [ ] 决定并配置实际可用的私密安全报告渠道，然后更新 `SECURITY.md`，不声明尚未启用的功能或联系地址。
- [ ] 由维护者选择真实版本号与发布范围，编写基于提交差异的发布说明，不用 API 内部版本字段冒充已发布版本。

建议先做可审阅的 PR，通过上述检查后再由维护者合并并决定创建 Release。准备分支、测试通过或生成 `dist/` 都不等同于已发布网站或版本。

## 建立持续维护流程

每次发布应记录目标提交、验证结果、用户可见变化、数据或配置兼容性以及已知问题。涉及存储格式时先说明备份与迁移；现有 JSON / SQLite 之间没有自动迁移工具。

改动应通过小范围 PR 讨论和审阅；Issue 中保留可复现信息。增加依赖时检查来源与许可，定期处理已知依赖问题。仅在真实提供持续维护后，再承诺支持版本和响应时间。

如果未来需要部署，需另行设计鉴权、授权、数据隔离、备份恢复与运行监控，并验证承载范围。静态前端托管不能让无鉴权 API 自动具备生产安全性；部署操作不属于本次开源准备。

## 后续方向

以下是按价值排序的候选工作，尚未承诺版本、日期或已经交付：

1. **可合法复用的样例**：用自有或有明确许可的短视频及笔记替换待核实素材，补全来源和署名，降低首次克隆成本。
2. **统一数据入口**：整理根目录演示副本和 `src/feed-data.js`，让缓存工具与 `src/data/feed.js` 共享明确的数据契约；迁移前保留当前行为验证。
3. **完整的失败体验**：继续完善存储空间不足、损坏本地数据、网络中断与导出失败的反馈，清楚显示存储位置。
4. **更易参与的界面**：逐步改善语义结构、键盘可达性、小屏交互和组件边界，避免用整体重写扩大维护成本。
5. **可选真实 AI 流程**：若有明确需求，再设计服务端模型接入、隐私告知、费用控制、取消与重试、来源引用和质量评估；当前没有该运行能力。
6. **面向服务的能力**：只有在明确需要多人使用后，再评估账号、授权、迁移、并发与可观测性，避免把本地单人原型直接当作多租户服务。
